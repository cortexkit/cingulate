# Flow-install secret approvals v1

Generated by Cingulate's real handlers in fresh scratch stores at
1700000000000 ms. The filer is `reserved:prefrontal-core`; the phone is the
callosum-stamped `fed-phone:11111111111111111111111111111111`, declaring
`clientFeatures: ["secret-use-approval"]`.

The first statement is byte-for-byte `golden:statement.flow` (and the decoded
`golden:request_flow_approval.result` statement) from Claustrum commit `1ee946f`,
`docs/wire-contract-v1.md` section 15. The second changes only the request id,
secret name and incarnation to represent a second secret. Refusals change only
the field named by the case. These are public fixtures, not credentials.

`filing.json` shows the two-secret install request as core sends it, without
`expires_in_ms`. `phone-get.json` shows its phone projection, with unchanged
nested vault bytes. `allow.json` carries the phone's canonical envelope;
`decline.json` requires no envelope. Remaining files show named filing and
answer refusals. Every file records method, params and the actual handler reply.
The envelope is not a signature: the vault verifies the phone's signature and
pairing, while Cingulate binds the exact envelope bytes to the card and route.

Regenerate with
`cargo run -p cingulate-vectors --example generate_flow_secrets_vectors --locked`.
Pass `-- --check` to compare without writing. The `flow_install_secrets`
integration test compares all handler bytes and verifies `SHA256SUMS` coverage.
