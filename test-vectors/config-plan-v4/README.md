# Config-plan v4 visibility and safe-diagnostic samples

Readers first: the phone must render the true-only launch-manifest
`program_changed_since_target` and `program_changed_since_active` flags,
`apply.rollback_programs` and the `route_rebind` module transition before
Callosum files them. Until the phone reader is live, Callosum keeps filing
these as other sections (Decline-only).

These samples preserve v3 request and success shapes. Compared with v3, pending-list
revisions gain `:config-plan` so changing the phone feature projection cannot reuse a
hidden-card cache; malformed-shape refusals use fixed messages rather than echoing
parser content. Each sample's corpus tag is updated to `config-plan-v4`.
The v1, v2 and v3 corpora and release tags remain unchanged. All names, hashes, statements and
signatures are invented; Cingulate carries signed bytes without interpreting
them. SHA256SUMS pins every sample and this README.

Generate from real handlers with
`cargo run -p cingulate-vectors --example generate_config_plan_vectors`.
Pass `-- --check` to verify every generated byte and SHA256SUMS, or
`-- --output DIRECTORY` to generate into a writable scratch directory.

- `rollback.json` includes both program-change flags and per-program rollback
  detail comparing `approved_then` with `on_disk_now`.
- `flag-only.json` has no origin or program rows: the required `programs` member
  is an empty array. A program or flag is required in every manifest entry.
- `route-rebind.json` shows a module that keeps running while its open
  connections close and reopen under the new settings.
- `false-program-flag.json`, `empty-manifest.json`, `missing-programs.json` and
  `rollback-programs-on-change.json` refuse a false flag, no program or flag,
  an omitted required programs array, and rollback detail on a change plan.

The remaining samples cover the existing typed sections, limits, approval,
decline, expiry, withdrawal, requester and phone reads, reopening and
round-bound answers. Nonempty `other_sections` remains Decline-only. The daemon's
config-gate plan emits `policy_changes` as a list; these samples preserve that
array shape in `other_sections.policy_changes` whenever the member is present.
The phone projection preserves all nested snake_case names unchanged.
