# Consent outcomes correlation and flags, v1

Served consent vectors for core outcomes. These records are captured through the
real Cingulate handler and pin the opaque `requester_ref`, optional `single_use`,
and settlement-time `late` fields. The cases cover a reference with single use,
a reference without it, a card with neither field, settlement while attached,
settlement after detach, and detach followed by a dedup refresh before settlement.
They also pin refusal of `single_use` on a non-consent kind and refusal of a
non-boolean value.

`single-use-get-reply.json` confirms requester reads retain the field, while
`single-use-phone-get-reply.json` confirms phone projections omit it. Existing
phone vector sets remain byte-for-byte unchanged.

`operator-app-*` captures an ordinary answer and outcome through a daemon-stamped
desktop route. `operator-app-peer.json` supplies the trusted peer stamp. The
outcome adds `answered_surface: "operator_app"` and has no phone device fingerprint.

Regenerate with:

```sh
cargo run -p cingulate-vectors --example generate_consent_outcomes_refs_vectors --locked
```

Compare regenerated bytes and file coverage with:

```sh
cargo run -p cingulate-vectors --example generate_consent_outcomes_refs_vectors --locked -- --check
cargo test -p cingulate-vectors --test consent_outcomes_refs --locked
```

`SHA256SUMS` covers every file in this directory except itself; the pin test
checks the manifest digest and exact file coverage.
