# Config-plan v2 typed-section samples

Readers first: the phone must render `apply`, `affected_projects`,
`policy_changes` and `launch_manifests` before Callosum files these members.
`other_sections` remains raw and makes a card Decline-only. Historical cards
without `apply` also remain readable but Decline-only.

These samples add typed sections to `consent-config-plan/v1`; they do not change
the existing `config-plan-v1` corpus or its release tag. A new tagged set
identifies these samples separately. All module/project names, hashes,
statements and signatures are invented. Cingulate carries signed bytes without
interpreting them.

Generate from real handlers with
`cargo run -p cingulate-vectors --example generate_config_plan_vectors`.
Pass `-- --check` to verify every generated byte and SHA256SUMS.
Use `-- --output DIRECTORY` to generate into a writable scratch directory when
the checked-out files are read-only.

`change-all-sections.json`, `rollback.json`, `program-only.json` and
`layer-file-only.json` include filing and phone readback. A `layer_file` row
means **settings file changed; no setting changed** and carries only file hash/
length or absence facts. The refusal samples cover an unknown transition, an
over-cap list, a missing apply summary, an empty plan and malformed layer-file
facts. Each new scenario carries the `config-plan-v2` tag.

The remaining samples cover list/get, requester get/await, answer, reopening,
two-round notices, decline, withdrawal, expiry and requester/answer refusals.
`stale-round.json` refuses a round-0 answer after reopening to round 1;
`statement-reused.json` refuses the old statement even with `expectedRound: 1`.
`second-answer.json` supplies that current round and fresh invented bytes.
The phone projection preserves every nested snake_case member unchanged.
